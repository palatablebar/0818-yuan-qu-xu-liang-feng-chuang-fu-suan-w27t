# 批次操作

1. 用带异常样例做阶段预览，查看列数、必填值和冲突记录。
2. 执行批次后，在业务阶段定位异常分组并核对原始记录键。
3. 查看每组的覆盖列：缺测窗口即使只少一只表也会留下覆盖记录。若缺测窗口已到读数达到候选峰值，签发被阻止，需按提示的分组与记录补表后重跑。
4. 修复来源文件，重新上传并执行。同一来源重跑复用批次、不新增记录；历史批次保留供复核，已签发证据不被覆盖。
5. 对账无差异、无坏行且无阻断分组时可签发；仅有低于峰值的缺测窗口时，可带覆盖范围放行。对仍有差异的版本可填写暂缓意见。
6. 导出复核证据并保存于交接记录。

单文件 256 KiB，最多 2000 条逻辑记录。容器重启后保留批次。恢复时使用原 Docker Compose 数据卷。
